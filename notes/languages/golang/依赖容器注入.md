```go
package di

import (
	"sync"
)

type Get func(serviceName string) interface{}

// ServiceConstructor defines the contract for a function/closure to create a service.
type ServiceConstructor func(get Get) interface{}

// ServiceConstructorMap maps a service name to a function/closure to create that service.
type ServiceConstructorMap map[string]ServiceConstructor

// service is an internal structure used to track a specific service's constructor and constructed instance.
type service struct {
	constructor ServiceConstructor
	instance    interface{}
}

// Container is a receiver that maintains a list of services, their constructors, and their constructed instances in a
// thread-safe manner.
type Container struct {
	serviceMap map[string]service
	mutex      sync.RWMutex
}

// NewContainer is a factory method that returns an initialized Container receiver struct.
func NewContainer(serviceConstructors ServiceConstructorMap) *Container {
	c := Container{
		serviceMap: map[string]service{},
		mutex:      sync.RWMutex{},
	}
	if serviceConstructors != nil {
		c.Update(serviceConstructors)
	}
	return &c
}

// Set updates its internal serviceMap with the contents of the provided ServiceConstructorMap.
func (c *Container) Update(serviceConstructors ServiceConstructorMap) {
	c.mutex.Lock()
	defer c.mutex.Unlock()
	for serviceName, constructor := range serviceConstructors {
		c.serviceMap[serviceName] = service{
			constructor: constructor,
			instance:    nil,
		}
	}
}

// get looks up the requested serviceName and, if it exists, returns a constructed instance.  If the requested service
// does not exist, it returns nil.  Get wraps instance construction in a singleton; the implementation assumes an instance,
// once constructed, will be reused and returned for all subsequent get(serviceName) calls.
func (c *Container) get(serviceName string) interface{} {
	service, ok := c.serviceMap[serviceName]
	if !ok {
		// Returning nil allows the DIC to be queried for a object and not panic if it doesn't exist.
		return nil
	}
	if service.instance == nil {
		service.instance = service.constructor(c.get)
		c.serviceMap[serviceName] = service
	}
	return service.instance
}

// Get wraps get to make it thread-safe.
func (c *Container) Get(serviceName string) interface{} {
	c.mutex.Lock()
	defer c.mutex.Unlock()
	return c.get(serviceName)
}

```

这个 Go 代码实现了一个简单的依赖注入容器（Dependency Injection Container，简称 DIC），用于管理服务的构造和获取。它支持线程安全的服务注册和单例模式的实例化。下面我将详细解释如何使用这个依赖注入容器，并提供具体示例。

---

### 1. 核心概念
+ **Container**：依赖注入容器的核心结构体，负责存储服务构造器（`ServiceConstructor`）和服务实例（`instance`）。
+ **ServiceConstructor**：一个函数类型，定义了如何构造一个服务实例。它接受一个 `Get` 函数作为参数，允许服务在构造时获取其他依赖。
+ **Get**：用于从容器中获取其他服务的函数，签名是 `func(serviceName string) interface{}`。
+ **单例模式**：容器确保每个服务只被构造一次，之后重复调用 `Get` 会返回相同的实例。
+ **线程安全**：通过 `sync.RWMutex` 实现线程安全，允许多个 goroutine 并发访问容器。

---

### 2. 使用步骤
要使用这个依赖注入容器，你需要：

1. 定义服务的构造器（`ServiceConstructor`）。
2. 创建一个 `Container` 实例并注册服务构造器。
3. 使用 `Container.Get` 获取服务实例。

以下是一个完整的示例，展示如何使用这个容器。

---

### 3. 示例代码
假设我们有一个简单的应用程序，包含两个服务：`Logger` 和 `UserService`。`UserService` 依赖于 `Logger`。

```go
package main

import (
    "fmt"
    "sync"
)

// Logger 是一个简单的日志服务
type Logger struct {
    prefix string
}

func (l *Logger) Log(msg string) {
    fmt.Printf("[%s] %s\n", l.prefix, msg)
}

// UserService 是一个依赖 Logger 的服务
type UserService struct {
    logger *Logger
}

func (us *UserService) CreateUser(name string) {
    us.logger.Log("Creating user: " + name)
}

// 依赖注入容器代码（与问题中的代码相同，略）
// 假设已放入 "di" 包中，导入为：
import "di"

// 服务构造器：构造 Logger
func newLogger(get di.Get) interface{} {
    return &Logger{prefix: "INFO"}
}

// 服务构造器：构造 UserService，依赖 Logger
func newUserService(get di.Get) interface{} {
    logger := get("logger").(*Logger) // 获取 Logger 依赖
    return &UserService{logger: logger}
}

func main() {
    // 1. 创建服务构造器映射
    constructors := di.ServiceConstructorMap{
        "logger":      newLogger,
        "userService": newUserService,
    }

    // 2. 初始化容器并注册服务
    container := di.NewContainer(constructors)

    // 3. 获取服务实例
    userService := container.Get("userService").(*UserService)

    // 4. 使用服务
    userService.CreateUser("Alice")

    // 5. 验证单例：再次获取 userService，应该是同一个实例
    userService2 := container.Get("userService").(*UserService)
    fmt.Printf("Same instance: %v\n", userService == userService2) // 输出：Same instance: true
}
```

运行输出：

```plain
[INFO] Creating user: Alice
Same instance: true
```

---

### 4. 使用步骤详解
#### 4.1 定义服务和构造器
+ 为每个服务定义一个结构体（如 `Logger` 和 `UserService`）。
+ 为每个服务实现一个构造器函数，符合 `ServiceConstructor` 类型：

```go
func(get di.Get) interface{}
```

    - 构造器使用 `get` 函数获取依赖（例如 `newUserService` 中获取 `logger`）。
    - 返回值是 `interface{}`，通常是服务结构体的指针。
+ 类型断言：在构造器中，`get` 返回的是 `interface{}`，需要使用类型断言（如 `get("logger").(*Logger)`）将其转换为具体类型。

#### 4.2 创建和注册容器
+ 使用 `di.NewContainer` 创建容器，并传入 `ServiceConstructorMap`：

```go
constructors := di.ServiceConstructorMap{
    "serviceName": constructorFunc,
}
container := di.NewContainer(constructors)
```

+ 也可以在容器创建后再调用 `container.Update(constructors)` 动态添加服务构造器。

#### 4.3 获取服务
+ 使用 `container.Get(serviceName)` 获取服务实例：

```go
service := container.Get("userService").(*UserService)
```

+ `Get` 是线程安全的，内部会：
    - 检查服务是否已注册。
    - 如果实例不存在，则调用构造器创建实例并缓存。
    - 返回缓存的实例（单例模式）。
+ 如果服务不存在，`Get` 返回 `nil`，不会引发 panic。

#### 4.4 单例模式
+ 容器确保每个服务只构造一次。第一次调用 `Get` 时，构造器被调用，实例被缓存。
+ 后续调用 `Get` 直接返回缓存的实例。

#### 4.5 线程安全
+ `Container` 使用 `sync.RWMutex` 确保线程安全，允许多个 goroutine 并发调用 `Get` 或 `Update`。
+ 读操作（`Get`）使用读锁，允许多个并发读取。
+ 写操作（`Update` 或实例化服务）使用写锁，防止并发修改。

---

### 5. 注意事项
1. **类型断言**：
    - `Get` 返回 `interface{}`，需要类型断言到具体类型（如 `(*UserService)`）。
    - 如果断言失败（例如服务未注册或类型不匹配），会引发 panic。建议在调用 `Get` 后检查返回值是否为 `nil`。
2. **依赖循环**：
    - 如果服务之间存在循环依赖（例如 A 依赖 B，B 依赖 A），会导致死锁或无限递归。
    - 解决方法：重构服务设计，避免循环依赖，或延迟依赖注入（例如通过 setter 方法）。
3. **服务未注册**：
    - 如果调用 `Get` 时服务未注册，返回 `nil`。建议在获取服务后检查返回值：

```go
if service := container.Get("unknown"); service == nil {
    fmt.Println("Service not found")
}
```

4. **单例模式限制**：
    - 容器默认使用单例模式。如果需要每次构造新实例，可以修改 `get` 方法逻辑，或者在服务内部实现工厂模式。
5. **性能**：
    - 构造器只在第一次 `Get` 时调用，性能开销较小。
    - 锁的使用可能在高并发场景下影响性能。如果性能敏感，可以考虑读写分离或减少锁粒度。
