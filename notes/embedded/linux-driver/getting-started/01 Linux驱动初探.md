
# Linux 设备驱动开发初探



## 一、Linux设备驱动开发基本概念

- 硬件是底层基础，软件运行的平台  
- 软件实现具体应用，适应多样化需求  
- 驱动程序是硬件与应用软件之间的沟通桥梁  
- 驱动工程师是硬件工程师与应用软件工程师之间的沟通桥梁  

在学习驱动之前，我们先了解一些基本概念：

### 概念一、裸机编程（单片机开发）
**定义**：  
直接在硬件上编程，无操作系统支持（如单片机开发环境）。  

**特点**：  
- 程序通过串口下载到芯片Flash中  
- 通常包含 `while(1)` 死循环保持运行  
- 主要应用于低端嵌入式系统（SCM-single chip machine、MCU、DSP、PC的bootloader等）  

**单片机简介**：  
- 集成CPU、随机存储器RAM、只读存储器ROM、I/O、中断系统、定时器等功能的小型芯片  
- 可能包含显示驱动、脉宽调制电路PWM、模拟多路转换器ADC等外设  

**开发内容**：  
1. **程序设计**：PC端编写控制逻辑  
2. **程序烧录**：通过编程器/下载线写入单片机  
3. **系统设计**：根据需求选型硬件（如开关控制、传感器等）  

### 概念二、Linux 系统开发
**定义**：  
基于Linux操作系统的产品开发，与裸机编程有本质区别。  

**驱动角色变化**：  

裸机开发直接运行在硬件之上，不与任何操作系统关联。操作系统的存在势必要求设备驱动附加更多的代码和功能，把单一的”驱使硬件设备行动“变成了操作系统内与硬件交互的模块，它对外呈现为操作系统的API，不再给应用软件工程师直接提供接口。由此，驱动程序变成了连接硬件与内核的桥梁。

**系统分层架构**：  

```
应用软件 → 操作系统 → 驱动程序 → 硬件
```

**跨硬件特性**：  

- 同一Linux系统可运行于不同硬件（如PC、ARM开发板）  
- 驱动需适配具体硬件架构（如x86驱动 ≠ ARM驱动）  
- 驱动是操作系统与硬件交互的唯一差异化组件  

**关键结论**：  
> 同一个操作系统可以跑到不同的硬件上，但是驱动程序是由差异的，应为驱动程序是操作系统和硬件连接的桥梁。

### 概念四、应用软件

应用软件的程序会调用Linux操作系统的函数来完成对硬件的操作，应用程序是不能对硬件直接操作。

### 概念五、Linux系统架构优点

1. Linux框架很成熟、完整，提供了很多现成的功能。
2. Linux框架让系统变得更安全，我们的应用软件不能直接对硬件操作，需要借助操作系统对硬件操作，若一个应用软件崩溃，不会影响到整个系统。

## 二、Linux设备驱动分类及特点

计算机系统的硬件主要由CPU、存储器和外设组成。随着IC制作工艺的发展，目前，芯片的集成度越来越高，往往在CPU内部就集成了存储器和外设适配器。譬如，相当多的ARM、PowerPC、MIPS等处理器都继承了UART、I2C控制器、SPI控制器、USB控制器、SDRAM控制器等，有的还继承了GPU、视频解码器等。

驱动针对的对象是存储器和外设（包括CPU内部集成的存储器和外设，而不针对CPU内核）。

Linux将存储器和外设分为3个基础大类：

- 字符设备驱动
- 块设备驱动
- 网络设备驱动

### 字符设备驱动

- 最为重要，因为快设备驱动和网络设备驱动已经做好了，只需要配置。

- 字符设备指的是那些必须以串行顺序依次进行访问的设备，如触摸屏、磁带驱动器、鼠标等。

### 块设备驱动

- 可以按任意顺序进行访问，以块为单位进行操作，如硬盘、eNNC等。

- 字符设备和块设备的驱动设计有很大的差异，但是对于用户而言，他们都是用文件体哦那个的操作接口 `open()`、`close()`、`read()`、`write()`等进行访问

### 网络设备驱动

- 网络设备，如wifi、以太网
- 网络设备面向数据包的接收和发送而设计，并不倾向对应于文件系统的节点。
- 内核与网络设备的通信和字符设备的通信方式是完全不同的，网络设备主要使用Socket套接字。
