在 FreeRTOS 中，**任务通知**（Task Notifications）是一种高效的任务间通信机制，用于在任务之间传递信号或数据。任务通知是一个轻量级的同步和消息传递机制，它不依赖于队列或信号量，因此比队列和信号量占用的资源少，执行效率也更高。

任务通知可以用于以下场景：

- **事件通知**：任务间的事件信号传递。
- **同步**：任务间的同步操作。
- **数据传输**：用于传递少量的数据（例如 32 位数据）。

### 任务通知的特性

1. **高效**：任务通知不需要额外的内存分配（如队列或信号量），因此它们的资源占用比其他通信机制小，适用于资源受限的系统。
2. **快速**：任务通知的处理速度非常快，适合需要低延迟的应用。
3. **灵活**：任务通知支持不同的通知模式和数据传递方式，可以通过直接传递数据或传递信号来实现任务间的通信。

### 任务通知的相关函数

#### 1. **`xTaskNotifyGive()`**

**描述**：通知一个任务，该任务可以被唤醒。

- **原型**：

  ```c
  BaseType_t xTaskNotifyGive(TaskHandle_t xTask);
  ```

- **参数**：

  - `xTask`：目标任务的句柄。任务通知只能通知指定的任务。

- **返回值**：

  - `pdTRUE`：成功发送通知。
  - `pdFALSE`：发送通知失败。

- **使用示例**：

  ```c
  if (xTaskNotifyGive(xTask) == pdTRUE) {
      // 成功通知任务
  }
  ```

#### 2. **`xTaskNotify()`**

**描述**：通知一个任务，可以指定通知的类型和数据。

- **原型**：

  ```c
  BaseType_t xTaskNotify(TaskHandle_t xTask, uint32_t ulValue, eNotifyAction eAction);
  ```

- **参数**：

  - `xTask`：目标任务的句柄。
  - `ulValue`：传递的数据值（32 位整数），可以用于传递小量的数据。
  - `eAction`：通知操作的类型，定义如下：
    - `eSetBits`：设置任务的通知状态（使用位掩码）。
    - `eIncrement`：将任务的通知值递增。
    - `eSetValueWithOverwrite`：设置任务的通知值（会覆盖原值）。
    - `eSetValueWithoutOverwrite`：设置任务的通知值（只有在原值为 0 时才设置）。

- **返回值**：

  - `pdTRUE`：成功发送通知。
  - `pdFALSE`：发送通知失败。

- **使用示例**：

  ```c
  if (xTaskNotify(xTask, 1, eSetBits) == pdTRUE) {
      // 成功设置通知
  }
  ```

#### 3. **`ulTaskNotifyTake()`**

**描述**：等待任务的通知，直到接收到通知或超时。

- **原型**：

  ```c
  uint32_t ulTaskNotifyTake(BaseType_t xClearCountOnExit, TickType_t xTicksToWait);
  ```

- **参数**：

  - `xClearCountOnExit`：是否在退出时清除任务通知的计数。
  - `xTicksToWait`：等待通知的最大时间（单位为 tick）。如果设置为 `0`，表示不等待，立即返回。

- **返回值**：

  - 返回通知值（32 位整数）。通常任务会检查返回值是否符合预期。

- **使用示例**：

  ```c
  uint32_t ulNotificationValue;
  ulNotificationValue = ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
  if (ulNotificationValue & 0x01) {
      // 根据接收到的通知值执行操作
  }
  ```

#### 4. **`xTaskNotifyWait()`**

**描述**：等待任务通知并清除指定的通知位。

- **原型**：

  ```c
  uint32_t xTaskNotifyWait(uint32_t ulBitsToClearOnEntry, uint32_t ulBitsToWaitFor, uint32_t *pulNotificationValue, TickType_t xTicksToWait);
  ```

- **参数**：

  - `ulBitsToClearOnEntry`：进入时要清除的通知位。
  - `ulBitsToWaitFor`：等待的通知位掩码。
  - `pulNotificationValue`：接收到的通知值。
  - `xTicksToWait`：等待通知的最大时间（单位为 tick）。

- **返回值**：

  - 返回任务的通知值。

- **使用示例**：

  ```c
  uint32_t ulNotificationValue;
  ulNotificationValue = xTaskNotifyWait(0, 0x01, &ulNotificationValue, portMAX_DELAY);
  if (ulNotificationValue & 0x01) {
      // 根据接收到的通知值执行操作
  }
  ```

------

### 任务通知的使用模式

任务通知支持以下几种常见的使用模式：

1. **通知任务执行操作**

   - 任务可以通过 `xTaskNotifyGive()` 向其他任务发送信号，表示某个事件发生或需要任务进行操作。例如，主任务可以通知从任务开始执行数据处理。

   **示例**：

   ```c
   // 主任务通知从任务
   xTaskNotifyGive(xSubTask);
   ```

2. **任务等待通知**

   - 任务可以通过 `ulTaskNotifyTake()` 等待通知。当目标任务完成其操作时，可以通过任务通知来唤醒正在等待的任务。

   **示例**：

   ```c
   uint32_t ulNotificationValue;
   // 从任务等待通知，直到接收到通知
   ulNotificationValue = ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
   if (ulNotificationValue & 0x01) {
       // 执行相关任务
   }
   ```

3. **传递数据**

   - 任务通知不仅限于信号传递，还可以通过通知传递少量数据。通过 `xTaskNotify()` 可以将一个 32 位的数据传递给接收任务。

   **示例**：

   ```c
   // 主任务传递数据
   xTaskNotify(xSubTask, 100, eSetValueWithOverwrite); // 设置数据值为 100
   ```

4. **等待多个通知**

   - 一个任务可以等待多个通知，使用 `xTaskNotifyWait()` 可以一次等待多个通知事件，或者等待通知并在满足某个条件时执行操作。

   **示例**：

   ```c
   uint32_t ulNotificationValue;
   // 等待通知并清除通知位
   ulNotificationValue = xTaskNotifyWait(0, 0x01, &ulNotificationValue, portMAX_DELAY);
   if (ulNotificationValue & 0x01) {
       // 执行相关操作
   }
   ```

------

### 总结

FreeRTOS 中的 **任务通知** 提供了一种高效、轻量级的任务间通信机制，具有以下优点：

- **高效性**：相比于队列和信号量，任务通知不需要额外的内存分配，处理速度快。
- **灵活性**：支持传递信号、数据、通知计数等多种模式。
- **适用场景**：任务通知适用于需要快速、高效传递信息或同步的任务间通信。

主要函数包括：

- **`xTaskNotifyGive()`**：通知任务进行操作。
- **`xTaskNotify()`**：传递信号或数据给任务。
- **`ulTaskNotifyTake()`**：任务等待通知。
- **`xTaskNotifyWait()`**：等待并清除通知位。

任务通知适用于实时性要求较高的应用，特别是在资源有限的系统中，能够有效减少内存开销和提高响应速度。
