# 校验检错
## 1 概述
在数据通信中，发送端会对传输的数据计算出校验码，并附在数据帧中发送给接收端，例如常见的奇偶校验和循环冗余校验（CRC）。接收端会对接收到的数据进行校验，以检测数据在传输过程中是否发生错误。如果发现错误，接收端会根据具体协议采取相应的措施，例如丢弃数据帧或请求重传。

常见的校验方法包括奇偶校验（Parity Check）、循环冗余校验（CRC）和帧校验序列（Frame Check Sequence, FCS）。其中，CRC 是一种常用的错误检测方法，能够检测出数据传输中的大部分错误。奇偶校验的检错能力较弱，而 CRC 和 FCS 则更为可靠，尤其是在检测突发错误（Burst Error）方面表现优异。

## 2 CRC 校验原理
### 2.1 基本概念
CRC 校验基于模 2 运算（即异或运算，XOR），是一种多项式除法运算。发送端将数据帧视为一个二进制多项式，并用一个预先确定的生成多项式（Generator Polynomial）进行除法运算，得到余数（Remainder）。这个余数就是 CRC 校验码，通常附加在数据帧的末尾，构成帧校验序列（FCS）。接收端收到数据后，用相同的生成多项式对数据（包含 FCS）进行除法运算。如果余数为 0，则说明数据传输无误；如果余数不为 0，则说明数据在传输过程中发生了错误。

### 2.2 CRC 校验过程
#### 示例 1：发送端计算 CRC 校验码
假设发送端的数据帧为一个 7 位二进制数 `1011001`，生成多项式为 `M=10101`（对应的二进制多项式为 (x<sup>4 + x</sup>2 + 1)）。

1. **步骤 1：补零操作**  
生成多项式的阶为 4（最高次幂为 (x^4)），因此需要在数据帧末尾补 4 个 0，得到 `10110010000`。
2. **步骤 2：模 2 除法**  
用生成多项式 `10101` 对补零后的数据帧 `10110010000` 进行模 2 除法（即异或运算）。模 2 除法的过程如下：

```plain
10110010000 ÷ 10101
10101 | 10110010000
        10101
        -----
         0011010000
          10101
          -----
           011110000
           10101
           -----
            1011000
            10101
            -----
             0001100
              10101
              -----
               01101 (余数 R)
```

除法结果的余数 (R = 1101)。

3. **步骤 3：生成 FCS 和完整数据帧**  
将余数 (R = 1101) 附加到原始数据帧 `1011001` 的末尾，得到完整的帧校验序列（FCS）：`10110011101`。  
此时，发送端将 `10110011101` 发送给接收端。

#### 示例 2：接收端验证 CRC 校验
接收端收到数据帧 `10110011101`，使用相同的生成多项式 `M=10101` 进行校验。

1. **步骤 1：模 2 除法**  
接收端用生成多项式 `10101` 对接收到的数据帧 `10110011101`（包含 FCS）进行模 2 除法：

```plain
10110011101 ÷ 10101
10101 | 10110011101
        10101
        -----
         0011011101
          10101
          -----
           011011101
           10101
           -----
            10111101
            10101
            -----
             00010101
              10101
              -----
               00000 (余数 R)
```

余数 (R = 0000)，说明数据传输无误。

2. **结论**  
如果余数为 0，则接收端认为数据无误，接受该数据帧。如果余数不为 0，则说明数据在传输过程中发生了错误，接收端会根据协议丢弃数据帧或请求重传。

### 2.3 CRC 校验的实际应用
在实际通信中，常用的 CRC 校验码包括 CRC-8、CRC-11 等。以 CRC-11 为例，其生成多项式为 `M=11001`，对应的帧校验序列为 `10110011101`，余数长度 (P = 1101)。

CRC 校验广泛应用于网络通信协议中，例如以太网、USB 和 CAN 总线等。它能够高效检测单比特错误、多比特错误以及突发错误，具有较高的可靠性。

## 3 补充说明
### 3.1 CRC 的优点
+ **高效性**：CRC 校验通过简单的异或运算实现，计算速度快，适合实时通信。
+ **可靠性**：能够检测大部分错误，尤其是突发错误，误检率低。
+ **灵活性**：通过选择不同的生成多项式，可以适应不同的数据长度和错误检测需求。

### 3.2 CRC 的局限性
+ **无法纠错**：CRC 只能检测错误，无法直接纠正错误。如果需要纠错，必须结合其他机制（如前向纠错 FEC）。
+ **依赖生成多项式**：生成多项式的选择会影响检错能力。如果生成多项式设计不当，可能无法检测某些特定类型的错误。

### 3.3 实际应用中的注意事项
在实际应用中，发送端和接收端必须使用相同的生成多项式，否则校验结果将不一致。此外，CRC 校验码的长度（即生成多项式的阶）需要根据数据帧的长度和错误检测需求进行选择。例如，CRC-8 适合短数据帧，而 CRC-32 更适合长数据帧（如以太网帧）。

### CRC 的数学原理
CRC 校验本质上是一种基于有限域（Galois Field, GF(2)）的多项式除法运算。数据帧和生成多项式都被视为二进制多项式。例如，数据帧 `1011001` 可以表示为多项式 (x<sup>6 + x</sup>4 + x<sup>3 + 1</sup><sup>)</sup><sup>，生成多项式 </sup>`10101`<sup> 表示为 </sup><sup>(</sup><sup>x</sup>4 + x^2 + 1)。模 2 除法的结果是余数，余数的位数等于生成多项式的阶。

### 常见 CRC 标准
以下是一些常见的 CRC 标准及其生成多项式：

+ **CRC-8**：生成多项式为 (x<sup>8 + x</sup>2 + x + 1)（二进制：`100000111`），常用于短数据帧。
+ **CRC-16-IBM**：生成多项式为 (x<sup>{16} + x</sup>{15} + x^2 + 1)（二进制：`11000000000000101`），常用于 IBM 协议。
+ **CRC-32**：生成多项式为 (x<sup>{32} + x</sup>{26} + x<sup>{23} + x</sup>{22} + x<sup>{16} + x</sup>{12} + x<sup>{11} + x</sup>{10} + x<sup>8 + x</sup>7 + x<sup>5 + x</sup>4 + x^2 + x + 1)（二进制：`100000100110000010001110110110111`），广泛用于以太网和 ZIP 文件校验。

### CRC 的误检率
CRC 的误检率（即错误未被检测到的概率）与生成多项式的选择和数据帧长度密切相关。对于一个好的生成多项式，误检率通常非常低。例如，CRC-32 的误检率在数据帧长度为 2<sup>14 字节时约为 </sup><sup>(</sup><sup>2</sup>{-32})，即 (2.3 \times 10^{-10})。

## 总结
CRC 校验是一种高效、可靠的错误检测方法，广泛应用于数据通信和存储领域。通过模 2 除法，发送端计算 CRC 校验码并附加到数据帧，接收端通过相同的生成多项式进行校验，判断数据是否正确。虽然 CRC 无法纠错，但其低误检率和高效率使其成为现代通信协议中不可或缺的一部分。
