这段文字描述了IP路由过程中，当路由器无法转发数据报时如何生成ICMP“主机不可达”差错报文，并结合具体的网络场景进行分析。以下是对内容的逐步解释：

---

### 背景知识
1. **ICMP主机不可达报文**
    - 当路由器收到一个IP数据报，但无法找到合适的路由将其转发到目标地址时，会生成一个ICMP（Internet控制消息协议）“主机不可达”（Type 3, Code 3）差错报文，返回给发送方。
    - ICMP报文的格式（文中提到图6-10）通常包括：ICMP头部 + 原始IP数据报的头部和部分数据（通常前8字节），以便发送方识别问题。
2. **路由表与默认路由**
    - 路由表决定数据报的转发路径。如果目标地址不匹配任何具体表项，会使用默认路由（default route，通常是`0.0.0.0/0`）。
    - 如果路由表中没有默认路由且无法匹配，路由器会丢弃数据报并返回ICMP差错报文。

---

### 场景1：SLIP链路断开时的主机不可达
#### 描述
+ 网络中有一个路由器`sun`，通过拨号SLIP（串行线路IP）链路连接其他主机。
+ 当SLIP链路断开时，试图通过该链路发送数据到以`sun`为默认路由的主机。

#### 路由表变化
+ **SLIP链路接通时**：路由表中会增加一条表项，使用SLIP链路（例如，目标网络通过SLIP接口）。
+ **SLIP链路断开时**：该表项被删除，`sun`的路由表中没有默认路由。
+ 其他主机的路由表未改变，仍然将`sun`作为默认路由。

#### 实验
+ 在主机`svr4`上运行`ping`，目标是SLIP链路另一端的主机（链路已断开）。
+ 在主机`bsdi`上运行`tcpdump`，捕获网络流量（图9-2）。

#### 结果
+ 路由器`sun`收到`ping`的ICMP回显请求（Echo Request）。
+ 由于SLIP链路断开，`sun`的路由表中没有到目标主机的路由（例如`gemini`）。
+ `sun`返回ICMP“主机不可达”报文给`svr4`。
+ `tcpdump`输出显示：`sun`响应了一个“主机不可达”的回显请求报文。

#### 系统差异
+ **老版本BSD**：可能返回“主机不可达”或“网络不可达”，取决于目标是否在同一子网。
+ **4.4 BSD**：只返回“主机不可达”，统一了行为。

#### 意义
+ 通过计数`sun`返回的ICMP“主机不可达”报文，可以验证路由失败的情况，而无需修改其他主机的默认路由。

### 场景2：SLIP链路连接Internet时的行为
#### 描述
+ 将SLIP链路连接到Internet，尝试`ping`一个未连接到Internet的IP地址。
+ 观察数据报在Internet中传播多远，以及差错报文如何返回。

#### 过程（参考图8-5）
+ 数据报从本地网络发出，经过6个路由器转发。
+ 每个路由器根据其路由表（包含默认路由）将数据报转发到下一跳。
+ 直到到达NSFNET骨干网的边界路由器，才检测到目标IP地址无效。
+ NSFNET边界路由器返回ICMP“主机不可达”报文。

#### 分析
1. **为什么经过6个路由器？**
    - 前6个路由器的路由表中有默认路由，允许它们将未知目标的数据报转发到下一跳。
    - 这些路由器只维护局部路由信息，不了解整个Internet的拓扑。
2. **为什么在NSFNET才发现错误？**
    - NSFNET骨干网是一个“顶层选路域”（top-level routing domain），维护大多数Internet网站的路由信息。
    - 它不依赖默认路由，而是知道每个连接到Internet的网络。
    - 当数据报到达NSFNET时，路由器发现目标IP没有对应的网络，因此返回差错报文。

#### 启示
+ Internet中的路由器分为两类：
    - **局部路由器**：依赖默认路由转发数据，只了解本地网络。
    - **顶层路由器**：维护全局路由信息，能准确判断目标是否可达。

---

### 顶层选路域（Top-Level Routing Domain）
#### 定义
+ 参考文献[Ford, Rekhter, and Braun 1993]提出，顶层选路域是Internet中维护大部分路由信息的核心网络，不使用默认路由。
+ 它们负责确保数据包最终到达正确目的地或识别不可达目标。

#### 例子
文中列举了5个顶层选路域：

1. **NSFNET骨干网**：美国国家科学基金会的网络，早期Internet核心。
2. **CIX（商业互联网交换）**：商业网络的互联点。
3. **NSI（NASA科学互联网）**：NASA的专用网络。
4. **SprintLink**：Sprint公司的骨干网络。
5. **欧洲IP主干网**：欧洲的Internet基础设施。

#### 作用
+ 这些网络通过维护详细的路由表，确保Internet的高效运行。
+ 默认路由在这些网络中不起作用，因为它们需要精确的路由决策。

---

### 总结
1. **SLIP链路断开实验**
    - 路由器`sun`因缺少路由表项，返回ICMP“主机不可达”。
    - 可通过`ping`和`tcpdump`验证这一行为。
2. **Internet传播实验**
    - 数据报因默认路由在Internet中传播，经过6跳才被NSFNET检测为不可达。
    - 揭示了局部路由器与顶层路由器的功能差异。
3. **路由哲学**
    - 局部网络依赖默认路由，简单高效。
    - 顶层网络（如NSFNET）依赖全局路由信息，确保准确性。
