

# 进程间通信

进程间通信的应用很广泛，如后台进程与GUI界面传递，发送关机信号，Ctrl+C终止正在运行的程序等。

Linux进程间通信机制分为三类：数据交互，同步，信号。

本章以常用的管道（有名、无名管道）、System V IPC（消息队列、共享内存、信号灯）、socket套接字（UNIX域套接字和网络套接字）为例来说明Linux进程通信常用的方法。进一步了解可以看专业的书。

# 01 无名管道

无名管道是最古老的进程通信方式，有如下两个特点：

- 只能用于有关联的进程间数据交互，如父子进程、兄弟进程、子孙进程，在目录中看不到文件节点，读写文件描述符存在一个int型数组中。
- 只能单向传输数据，即管道创建好后，一个进程只能进行读操作，另一个进程只能进行写操作，读出来字节顺序和写入的顺序一样。

| 函数           | int pipe(int pipefd[2]) //创建无名管道                       |
| -------------- | ------------------------------------------------------------ |
| 头文件         | #include <unistd.h>                                          |
| 参数 pipefd[0] | 一个int型数组，表示管道的文件描述符，pipefd[0]为读，pipefd[1]为写 |
| 返回值         | 成功返回0，失败返回-1                                        |

![image-20250715110851916](https://raw.githubusercontent.com/clint456/PicGo/main/Linux%E9%A9%B1%E5%8A%A8/image-20250715110851916.png)

无名管道使用步骤：

1. 调用`PIPE()`创建无名管道

2. `fork()`创建子进程，一个进程读，使用`read()`，一个进行写，使用`write()`

   ```c
   // 实验代码：通过无名管道实现父子进程通信，父进程从写入管道，子进程从管道读数据，并打印出来。
   #include <stdio.h>
   #include <stdlib.h>
   #include <sys/stat.h>
   #include <sys/wait.h>
   #include <unistd.h>
   int main(void) {
     char buf[32] = {0};
     pid_t pid;
     // 定义变量用来保存文件描述符
     // 一个为读、一个为读
     int fd[2];
     // 创建无名管道
     pipe(fd);
     printf("fd[0] is %d\n", fd[0]);
     printf("fd[1] is %d\n", fd[1]);
     // 创建进程
     pid = fork();
     if (pid < 0) {
       printf("error\n");
     }
     if (pid > 0) {
       int status;
       close(fd[0]);
       write(fd[1], "hello", 5);
       close(fd[1]);
       exit(0);
     }
     if (pid == 0) {
       close(fd[1]);
       read(fd[0], buf, 32);
       printf("buf is %s\n", buf);
       close(fd[0]);
       exit(0);
     }
     return 0;
   }
   ```

# 02 有名管道

有名管道中可以很好的解决在无关进程间进行数据交换的要求，并且由于它们是存在于文件系统中的，这也提供了一种比匿名管道更持久稳定的通信方法。有名管道又叫命名管道。

- 可以使得无关联的进程通过fifo文件描述符进行数据传递；
- 单向传输有一个写入端和一个读出端，操作方式和无名管道相同。

| 函数         | int mkfifo(const *pathname, mode_t mode)          |
| ------------ | ------------------------------------------------- |
| 头文件       | #include <sys/types.h><br />#include <sys/stat.h> |
| 参数pathname | 有名管道的路径和名称                              |
| 参数mode     | 权限                                              |
| 返回值       | 成功返回0，失败返回-1                             |

有名管道使用步骤：

1. 使用`mkfifo()`创建fifo文件描述符；

2. 打开管道文件描述符；

3. 通过读写文件描述符进行单向数据传输。

   ```basg
   mkfifo fifo # 创建fifo文件
   ls
   ls -al
   ```

# 03 信号

## 一、信号发送

信号是Linux系统响应某些条件而产生的一个事件，接收到该信号的进程会执行相应的操作。

信号的产生会有三种方式：

-  由硬件产生，如从键盘输入Ctrl+C可以终止当前进程。
- 由其它进程发送，如shell进程下，使用kill -<信号标号> PID, 向指定进程发送信号。
- 异常，进程异常时会发送信号。

## 二、信号接收
 接收信号：如果要让我们接收信号的进程可以接收到信号，那么这个进程就不能停止。让进程不停止有三种方法：

- `while`
- `sleep`
- `pause`

| 函数      | 说明                        |
| --------- | --------------------------- |
| **pause** | `int pause(void)`           |
| 头文件    | `#include <unistd.h>`       |
| 返回值    | 进程被信号中断后一直返回 -1 |
| 功能      | 暂停进程，等待信号          |

示例代码

```c
#include <stdio.h>
#include <unistd.h>

void main(void)
{
    printf("pause before\n");
    pause();
    printf("pause after\n");
}
```

## 三、信号处理

信号是由操作系统来处理的，说明信号的处理在内核态，信号不一定会被立即处理，会存储在信号的信号表中。

处理过程示意图：

![image-20250715170136752](https://raw.githubusercontent.com/clint456/PicGo/main/Linux%E9%A9%B1%E5%8A%A8/image-20250715170136752.png)

### 由 signal() 注册信号处理函数

#### 说明

1. 默认方式（通常终止进程）。
2. 忽略，不进行任何操作。
3. 捕捉并处理调用信号处理函数（回调函数形式）。

#### signal()

- `#include <signal.h>`
- `typedef void (*sighandler_t)(int);`
- `sighandler_t signal(int signum, sighandler_t handler);`

#### 参数
- `signum`: 信号值，参考 2)
- `handler`: 信号处理函数指针，参考 1)

#### 返回值
- 成功: 0
- 失败: -1（参考 errno）

#### 功能
- 注册信号处理函数
- 常用信号: `SIGINT`, `SIGKILL`, `SIGTERM`
- 特殊信号: `SIG_IGN` (忽略信号), `SIG_DFL` (默认处理)

#### 实验1、代码实现信号忽略
```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

int main(void) {
  signal(SIGINT, SIG_IGN);
  // 忽略Ctrl+C信号
  while (1) {
    printf("wait a signal\n");
    sleep(1);
  }
  return 0;
}
```

#### 实验2、代码实现采用系统默认方式处理该信号

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>
int main(void) {
  signal(SIGINT, SIG_DFL);
  while (1) {
    printf("waite signal \n");
    sleep(1);
  }
  return 0;
}
```

按下Ctrl+C可以终止程序。

#### 实验3、代码实现捕获到信号后执行阐述的内容、

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void myfun(int sig)
{
    if (sig == SIGINT) {
        printf("get sigint\n");
    }
}

int main(void)
{
    signal(SIGINT, myfun);
    while (1) {
        sleep(1);
        printf("wait signal\n");
    }
    return 0;
}
```

# 04 共享内存

## 共享内存概述

就是允许两个不相关的进程访问同一个逻辑内存，共享内存是两个正在运行的进程之间共享和传递数据的一种非常有效的方式。不同的进程之间共享的内存通常为一段物理内存。进程可以将同一段物理内存连接到他们自己的地址空间中，所有的进程都可以访问共享内存的地址。如果某个进程向共享内存写入数据，所作的改动将立即影响到可以访问同一段共享内存的任何其它进程。

Linux操作系统的进程通常使用的是虚拟内存，虚拟内存空间是由物理内存映射而来的。System V共享内存能够实现让两个或多个进程访问同一个段物理内存空间，达到数据交互的效果。

![image-20250715173525969](https://raw.githubusercontent.com/clint456/PicGo/main/Linux%E9%A9%B1%E5%8A%A8/image-20250715173525969.png)

共享内存和其它进程间数据交互相比，有以下爱几个突出特点：

1. 速度快，因为共享内存不需要内核控制，所以没有系统调用的切换。而且没有向内核拷贝数据的过程，所有效率和前面几个相比是最快的，可以用来进行批量数据的传输，如图片。
2. 没有同步机制，需要借助Linux提供其它工具来进行同步，通常使用信号灯。

使用共享内存的步骤：

1. 调用`shmget()`创建共享内存段id；
2. 调用`shmat()`将id标识的共享内存段加载到进程的虚拟地址空间；
3. 访问加入到进程的那部分映射后地址空间，可用IO操作读写。

## System V IPC介绍

System V IPC包括三种进程间通信机制，有消息队列、信号灯（或叫信号量)、共享内存。此外还有System V IPC的补充版本POSIX IPC，这两组的IPC的通信方法基本一致，本章一System IPC为例介绍Linux进程通信机制。

可以用`ipcs`查看三种IPC，`ipcrm`删除IPC对象。

## 实验代码二：父子进行共享内存通信

```c
#include <stdio.h>      // 标准输入输出库
#include <stdlib.h>     // 标准库，包含 exit
#include <string.h>     // 字符串操作库，包含 strncpy
#include <sys/ipc.h>    // IPC 相关函数，包含 ftok
#include <sys/shm.h>    // 共享内存相关函数，包含 shmget, shmat
#include <sys/types.h>  // 基本数据类型定义
#include <sys/wait.h>   // 包含 wait 函数
#include <unistd.h>     // 包含 fork 和 sleep

int main(void) {
  int shmid;            // 共享内存标识符
  key_t key;            // IPC 键值
  pid_t pid;            // 进程 ID
  char *s_addr, *p_addr; // 共享内存指针

  key = ftok("./a.c", 'a'); // 生成 IPC 键值，基于文件 ./a.c 和项目 ID 'a'
  printf("ftok ./a.c result is %d\n", key); // 打印 ftok 返回值
  shmid = shmget(key, 1024, 0777 | IPC_CREAT); // 创建 1024 字节共享内存，权限 0777
  if (shmid < 0) {
    printf("shmget is error\n"); // shmget 失败提示
    return -1;                   // 退出程序
  }
  printf("shmget is ok and shmid is %d\n", shmid); // 成功提示并打印 shmid
  pid = fork(); // 创建子进程
  if (pid > 0) {                                    // 父进程
    p_addr = shmat(shmid, NULL, 0);                 // 映射共享内存
    strncpy(p_addr, "hello", 5);                    // 写入 "hello"
    wait(NULL);                                     // 等待子进程
    exit(0);                                        // 退出
  }
  if (pid == 0) {                                   // 子进程
    sleep(2);                                       // 暂停 2 秒
    s_addr = shmat(shmid, NULL, 0);                 // 映射共享内存
    printf("s_addr is %s\n", s_addr);               // 打印共享内存内容
    exit(0);                                        // 退出
  }

  return 0; // 程序结束
}
```

ftok 函数的作用是根据一个已有的文件路径和一个项目 ID 生成一个唯一的 IPC 键值（key_t 类型），该键值用于标识系统中的共享内存、信号量或其他 IPC 对象。如果当前目录下没有 ./a.c 文件，ftok 会失败并返回 -1。

## 共享内存的优缺点:

- **优点**：我们可以看到共享内存进行进程之间的通信是非常方便的，而且函数的接口也比较简单，数据共享还使用进程间的数据不用传送，而是直接访问内存，加快了程序的效率。
- **缺点**：共享内存没有通过同步机制，这使得我们在使用共享内存进行进程之间的通信时，往往需要借助其它手段来保证进程之间的同步工作。

# 05 消息队列

消息队列是类unix系统中的一种数据传输机制，其它操作系统中也实现了这种机制，可见其在操作系统中的重要地位。

Linux内核为每一个消息队列对象维护一个`msqid_ds`，每个`msqid_ds`对应一个id，消息以链表的形式存储，并且`msqid_ds`存放着这个链表的信息。

![image-20250716103834210](https://raw.githubusercontent.com/clint456/PicGo/main/Linux%E9%A9%B1%E5%8A%A8/image-20250716103834210.png)

## 消息队列的特点

- 发出的消息以链表形式存储，相当于一个列表，进程可以根据id向对应的`列表`增加和获取消息。
- 进程接收数据时，可以按照类型从队列中获取数据。

## 消息队列的使用步骤

1. 创建key;
2. `msgget()`通过key创建（或打开）消息队列对象id；
3. 使用`msgsnd()/msgrcv()`进行收发；
4. 通过`msgctl()`删除ipc对象。

# 06 信号量

**本章节将讨论另一种程序间通信的机制——信号量。**

注意事项：不要把它与前所述的信号混淆，信号与信号量不是同一种东西。为了防止出现图形窗口和一个共享资源之间的系列问题，我们需要一种方法，它可以通过允许在任何时间只给每个任务分配一个执行线程来更新代码逻辑。临界区就是在这种场景下的一个概念，信号量可以控制对临界区的访问，从而确保在任何时刻只有一个进程或线程可以访问该区域。

**信号量（Psv）：**

信号量是一种特殊的原语，它具有两种主要操作。首先是“等待”操作，即（信号量值减1）。信号量值是一个整数，通常为0和1之间，这个值表示资源的占有状态。如果信号量的值小于或等于0，则该资源无法获得，必须等待。另一方面，当资源可用时，它将执行另一操作，即信号量值加1。

- **P(sv)**：如果 sv 的值大于零，信号量将减少 1；如果它的值为零或负值，它将进入阻塞状态，直到信号量的值为正。
- **V(sv)**：如果 sv 的值为负，它将使其恢复到正值，或者如果 sv 的值已经为正，它会使其递增。

**举个例子**，就需要两个进程来进行信号量操作，一个进程执行了 P(sv) 操作，它将获得该资源，并可以进入临界区，而另一个进程被阻塞在临界区外，因为它无法满足 P(sv) 所需的条件。当第一个进程释放资源，信号量值增加后，第二个进程便能获得执行的机会。

**使用 System V 信号量的基本步骤：**

1. 使用 semget() 创建或打开一个信号量集。
2. 使用 semctl() 初始化信号量的值。
3. 使用 semop() 操作信号量值，即进行 P/V 操作。

**解释参数：**

- **P操作**：申请资源，资源值减1。
- **V操作**：释放资源，资源值加1。

Linux 提供了一组用于操作信号量的系统调用，它们用于实现进程间的同步。下面的代码示例展示了如何使用这些系统调用：

~~~c
// struct sembuf`结构体定义：
```c
struct sembuf {
    unsigned short sem_num; // 要操作的信号量的编号
    short sem_op;  // P/V 操作：1 为 V 操作（释放资源），-1 为 P 操作（分配资源），0 为等待直到信号量值为 0
~~~

```c
#include <fcntl.h>          // 文件控制定义
#include <stdio.h>          // 标准输入输出定义
#include <sys/ipc.h>        // IPC 机制相关定义
#include <sys/sem.h>        // 信号量相关定义
#include <sys/types.h>      // 系统数据类型
#include <unistd.h>         // UNIX 标准函数定义，如 fork/sleep

#define EXIT_SUCCESS 0      // 定义成功退出的返回值

// 定义 semun 联合体，这是 semctl 用来设置信号量值时需要的参数结构
union semun {
  int val;  // 用于 SETVAL 命令，表示信号量的初始值
};

int main(void) {
  int semid;                // 信号量集合的 ID
  int key;                  // 用于 semget 的 key
  pid_t pid;                // 进程 ID
  struct sembuf sem;        // 信号量操作结构体
  union semun semun_union;  // 信号量联合体，用于设置信号量初始值

  // 使用 ftok 生成一个唯一的 key，"./a.c" 是路径名，0666 是项目 ID（只是一个数字，不是权限）
  key = ftok("./a.c", 0666);

  // 创建一个包含 1 个信号量的集合，权限为 0666，若已存在则返回其 ID
  semid = semget(key, 1, 0666 | IPC_CREAT);

  // 将信号量的初始值设置为 0，表示阻塞状态
  semun_union.val = 0;
  semctl(semid, 0, SETVAL, semun_union);

  // 创建子进程
  pid = fork();

  if (pid > 0) {
    // 父进程逻辑

    // 准备执行 P 操作（等待/阻塞，-1）
    sem.sem_num = 0;  // 第 0 个信号量
    sem.sem_op = -1;  // P 操作（减 1，若为 0 则阻塞）
    sem.sem_flg = 0;
    semop(semid, &sem, 1);  // 执行 P 操作，等待子进程释放

    // 子进程释放信号量后，继续执行
    printf("This is parents\n");

    // 执行 V 操作（释放资源，加 1），结束前释放信号量
    sem.sem_op = 1;
    semop(semid, &sem, 1);
  }

  if (pid == 0) {
    // 子进程逻辑

    sleep(0);  // 可省略，此处无实际等待效果

    // 执行 V 操作（加 1），唤醒父进程
    sem.sem_num = 0;
    sem.sem_op = 1;
    sem.sem_flg = 0;
    semop(semid, &sem, 1);

    // 输出子进程信息
    printf("This is son\n");
  }

  return EXIT_SUCCESS;
}
```

**总结：**

信号量是一个特殊的变量，成都对其访问都是原子操作，且只允许对它进行等待（P）和发送（V）信息操作。我们通常通过信号来解决多个进程对同一资源的访问竞争的问题，使在任意时刻只能有个一个执行线程访问代码的临界区域，即**他是协调进程间对同一资源的访问权，即用于同步进程。**
