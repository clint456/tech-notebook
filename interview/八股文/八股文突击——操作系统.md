# 1.进程和线程的区别？
+ 进程是系统进行资源分配和调度的基本单位；
+ 线程是进程的子任务，是进程的执行单元；
+ 一个进程至少有一个线程，一个进程可以运行多个线程，这些线程共享同一个块内存。

### <font style="color:#5b9bd5;">内存开销：</font>
![](https://cdn.nlark.com/yuque/0/2025/png/33522184/1739110056133-18a9c24c-3e7e-4eb8-adeb-092227af4dfa.png)

### <font style="color:#5b9bd5;">通信与同步：</font>
+ 进程：由于进程间内存相互隔离，进程之间的通信需要使用一些特殊机制，如管道、消息队列、共享内存等；
+ 线程：由于线程共享相同的内存空间，他们之间可以共享内存数据，线程间通信会更加方便。

### <font style="color:#5b9bd5;">安全性：</font>
+ 进程：由于进程间相互隔离，一个进程奔溃不会直接影响其他进程的稳定性；
+ 线程：由于线程内是共享的内存，如果一个线程出现问题可能会导致影响整个进程的稳定性。



# 2.进程调度算法了解多少？
+ 进程调度算法是操作系统中**<font style="color:#c00000;">管理和调度进程执行的方法。</font>**
+ 这些算法决定了在多任务环境下，系统如何为各个进程分配CPU时间
+ 目的是：实现公平性、高吞吐量、低延迟等不同的调度目标

| 先来先服务调度算法 | 按照进程到达的先后顺序进行调度，最早到达的进程先执行，直到完成或阻塞 |
| --- | --- |
| 最短作业优先调度算法 | 优先选择运行时间最短的进程来运行<br/> |
| <font style="color:black;background-color:#808000;">高响应比优先调度算法</font> | 综合考虑等待时间和服务时间的比率，每个进程在一个时间片内运行，然后切换到下一个进程 |
| 时间片轮转调度算法 | 将CPU时间划分为时间片（时间量），每个进程在一个时间片内运行，然后切换到下一个进程（轮询） |
| 最高优先级调度算法 | 为每个进程分配一个优先级，优先级较高的进行先执行。这可能导致低优先级的进程长时间等待，引发饥饿问题 |
| 多级反馈队列调度算法 | 将进程划分为多个队列，每个队列具有不同的优先级，进程在队列之间移动。具有更高优先级的队列进程会更早执行，长时间的等待的进程会被提升到更高优先级队列。 |
| 最短剩余时间优先 | 每次选择剩余执行时间最短的进程来执行 |
| <font style="color:black;background-color:#808000;">最大吞吐量调度</font> | 旨在最大化单位时间内完成的进程数量 |


# 3.进程间有哪些通信方式？
## <font style="color:#DF2A3F;">管道</font>：
+ 一种<font style="color:#DF2A3F;">半双工</font>通信方式，数据只能进行单项流动，且只能在具有父子进程关系的进程间使用。

## 命名管道：
+ 一种半双工通道，但是它允许无亲属关系的进程间进行通信。

## <font style="color:#DF2A3F;">信号量</font><font style="color:#262626;">：</font>
+ <font style="color:#262626;">是一个计数器，可以用来控制多个进程对共享资源的访问，常作为一种锁机制，防止某个进程正在访问共享资源时，其他进程也访问该资源。因此主要作为进程间以及同一进程内不同进程之间的同步手段。</font>

## <font style="color:#DF2A3F;">消息队列</font><font style="color:#000000;">：</font>
+ <font style="color:#000000;">消息队列是消息的链表，存放在内核中并由消息队列标识符标识。消息队列克服了</font><font style="color:#DF2A3F;">信号传递信息少、管道只能承载无格式字节流以及缓冲区大小受限制</font><font style="color:#000000;">等缺点。</font>

## <font style="color:#000000;">信号：</font>
+ <font style="color:#000000;">用于通知接受进程某个事件已近发生，从而迫使进程执行信号处理程序。</font>

## <font style="color:#DF2A3F;">共享内存</font><font style="color:#000000;">：</font>
+ <font style="color:#000000;">就是映射一段能被其他进程所访问的内存，这段共享内存由一个进程创建，但多个进程都可以访问。共享内存所最快的进程通信方式，它是针对其他进程通信方式运行效率低而专门设计的。它往往与其他通信机制，比如信号量配合使用，来实现进程间的同步和通信。</font>

## <font style="color:#000000;">Socket套接字：</font>
+ <font style="color:#000000;">是支持TCP/IP的网络通信的基本操作单元，主要用于在客户端和服务器之间，通过网络进行通信。</font>

# <font style="color:#000000;">4.什么是死锁？如何避免死锁？</font>
## <font style="color:#000000;">死锁上是什么：</font>
<font style="color:#DF2A3F;">指两个或多个进程在争夺系统资源时，由于相互等待对方释放资源而无法继续执行的状态</font><font style="color:#000000;">。</font>

+ <font style="color:#000000;">死锁只有同时满足以下四个条件才会发生：</font>
    - 互斥条件：一个进程占用了某个资源时，其他进程无法同时占用该资源（哲学家使用筷子）。

![](https://cdn.nlark.com/yuque/0/2025/png/33522184/1739112801705-19d2cf60-b27a-4736-b181-b285fec9630c.png)

    - 请求保持条件：一个线程因为请求资源而阻塞的时候，不会释放自己的资源。
    - 不可剥夺条件：资源不能被强制性地从一个进程中剥夺，只能由持有者自愿释放。
    - 环路等待条件：多个进程之间形成一个循环等待的链，每个进程都在等待下个进程所占有的资源。

## 如何避免死锁：
    - 预防死锁：破坏死锁上面的必要条件，只需要破坏上面一个条件就可以破坏死锁：
        * 破坏请求与保持条件：一次性申请所有的资源。
        * 破坏不可剥夺条件：占用部分资源的线程，近一个申请其他资源时，如果申请不到，可以主动释放它占有的资源。
        * 破坏循环等待条件：靠<font style="color:#DF2A3F;">按照顺序申请资源</font>来预防。让所有进程按照相同的顺序请求资源，释放资源则反序释放。
    - 避免死锁：避免系统进入不安全的状态（银行家算法）
    - 死锁的检测与解除：允许死锁的发生，系统对死锁进行检测并解除

# 5.什么是虚拟内存？为什么需要虚拟内存？
## 虚拟内存是什么
<font style="color:#000000;">虚拟内存在每一个进程创建加载过程中，会分配一个连续虚拟地址空间，它</font>**<font style="color:#000000;">不是真实存在</font>**<font style="color:#000000;">的，而是通过</font><font style="color:#DF2A3F;">映射与实际地址空间对应</font><font style="color:#000000;">，这样就可以使每一个进程看起来都有自己独立的连续地址空间，并允许程序访问比物理内存RAM更大的地址空间，每个程序都可以认为它拥有足够的内存来运行。</font>

## <font style="color:#000000;">需要虚拟内存的原因</font>
+ 内存扩展：虚拟内存使得每个程序都可以使用比实际可用内存更多的内存，从而允许允许更大的程序或处理更多的数据。
+ 内存隔离：虚拟内存还提供了进程之间的内存隔离。每个进程都有自己的虚拟地址空间，因此，一个进程无法直接访问另一个进程的内存。
+ 物理内存管理：虚拟内存允许操作系统动态地将数据和程序的部分加载到物理内存中，以满足当前正在运行的进程的需求。当物理内存不足时，操作系统可以将不常用的数据或程序暂时移动到硬盘上，从而释放内存，以便其他进程使用。
+ 页面交换：当物理内存不足时，操作系统可以将一部分数据从物理内存写入到硬盘的虚拟内存中，这个过程被称之为页面交换。当需要时，数据可以再次从虚拟内存中加载到物理内存中。这样可以保证系统继续运行，尽管物理内存有限。
+ 内存映射文件：虚拟内存还可以用于将文件映射到内存中，这使得文件的读取和写入可以像访问内存一样高效。

# 6.什么是内存分段和分页？作用是什么？
## 内存分段
内存分段是将一个程序的内存空间分为不同的逻辑段（Segments），每个段代表程序的一个功能模块或数据类型，如：代码段、数据段、堆栈段等。每个段都有自己的大小和权限。

## 内存分页
内存分页是将整个虚拟和物理内存空间分成固定大小的页（如4kb）。这样一个连续并且尺寸固定的内存空间，我们叫做（Page）

## 他们的作用
1. 逻辑隔离：内存分段和分页都实现了程序的逻辑隔离，使得不同的功能模块或数据类型能够被单独管理和保护，提高了程序的可靠性和安全性。
2. 内存保护：通过将不同的段或页面设置为只读、可读写、不可知性等权限，操作系统可以确保程序不会越界访问或修改其他段等内容，从而提高了系统的稳定性。
3. 虚拟内存：分段和分页都有助于实现虚拟内存的概念，允许应用程序认为他们在使用的是一个比实际物理内存更大的内存空间。
4. 内存共享：通过分页，操作系统可以实现内存页面的共享，从而节省内存空间，多个进程可以共享相同的代码或数据页面。
5. 内存管理：分页更加灵活，允许操作系统将不同进程的页面分散存放在物理内存中，从而提高内存利用率。分段则更适用于管理不同的逻辑模块。

## 分段与分页的区别


|  | **对用户** | **地址空间** | **访问一个逻辑地址** | **信息的共享和保护** |
| :---: | :---: | :---: | :---: | :---: |
| 分页 | 不可见 | 一维的 | 需要两次访存 | 不容易实现 |
| 分段 | 可见 | 二维的 | 需要两次访存   可以引入快表机制 | 容易实现 |


## 分担与分页优缺点：
+ 分页管理：内存空间利用率高，不会产生外部碎片，只会有少量的页内碎片。但是不方便按照逻辑模块实现信息的共享和保护。
+ 分段管理：很方便按照逻辑模块实现信息的共享和保护。但是**如果段长过大，为其分配很大的连续空间会很不方便，段式管理会产生外部碎片**。

# 7.解释用户态和核心态
> 用户态和核心态，是操作系统中两种不同的执行模式，**<font style="color:#DF2A3F;">用于控制进程或程序对计算机硬件资源访问权限和操作范围</font>**。
>

## 用户态（User Mode）：
在用户态下，进程或程序只能访问受限的资源和执行受限的指令集，不能直接访问操作系统的核心部分，也不能直接访问硬件资源，用户态下的 CPU 不允许独占，也就是说 CPU 能够被其他程序获取。

## 核心态（Kernel Mode）：
核心态是操作系统的特权级别，允许进程或者程序执行特权指令和访问操作系统的核心部分。在核心态下，进程可以直接访问硬件资源，执行系统调用，管理内存、文件系统等操作。处于内核态的 CPU 可以从一个程序切换到另一个程序，并且 CPU 不会发生抢占情况，一般处于特权级 9 到状态我们称之为内核态。

# 8.解释页面置换算法，例如 LRU（最近最少使用），FIFO（先进先出）等
## 情景举例：
> 假设你的手机内存有限，只能同时运行四个原神角色。当你想切换到一个新角色时，你需要从内存中换出一个旧角色，以便为新的角色腾出空间。不同的页面置换算法就相当于不同的切换策略。
>

例如：

+ **<font style="color:#DF2A3F;">LRU（最近最少使用）算法</font>**：每次选择最长时间没有被使用过的角色进行切换。这种策略基于你对角色的喜好，认为最近被使用过的角色很有可能还会被使用，而最久没有被使用的角色很有可能不会再被使用。LRU 算法可以有效地减少切换次数，但是实现起来比较复杂，需要记录每个角色的使用时间或维护一个使用顺序列表。
+ **<font style="color:#DF2A3F;">FIFO（先进先出）算法</font>**：每次选择最早进入内存的角色进行切换。这种策略很简单，只需要维护一个角色对列，每次淘汰队首对角色，然后把新的角色加入队尾。但是 FIFP 算法可能会淘汰一些经常被使用的角色，导致切换次数增加。而且 FIFO 算法很有可能出现贝拉迪异常 （Belady anomaly)，即当分配给内存的空间增加时，切换次数而增加。

> 常见页面置换算法有
>
> + 最佳置换算法（OPT）
> + 先进先出（FIFO）
> + 最近最久未使用算法（LRU）
> + 时钟算法（Clock）
>

## 最佳置换算法
该算法**根据未来的页面访问情况，选择最长时间内不会被访问到的页面置换**。那么会出现一个问题“未来要访问什么操作页面，操作系统怎么知道的呢？”

答案是，操作系统当然不会知道，所以这种算法只是一种理想情况下的置换算法，通常时无法实现的。

## 先进先出算法
也就是**<font style="color:#DF2A3F;">最先进入内存的页面最先置换出去</font>**。这个算法比较简洁明了，就不过多解释。

但是先进先出算法会存在一个问题，就是 Belady 问题（随着分配给进程的空闲页面书增加，缺页的情况反而也会增加）。

这与我们的常识相悖的，因为我们通常认为如果一个进程经常发生缺页，那么就应该为他多分配一点内存，然而使用 FIFO 算法时，反而可能导致更多的缺页情况出现，这种情况只会在 FIFO 算法中出现。

## 最近最久未使用算法
LRU 算法**<font style="color:#DF2A3F;">基于页面的使用历史，通过选择最长时间为被使用的页面进行置换</font>**。

+ 核心思想：最近被访问的页面可能在未来被再次访问，而最长时间未被访问的页面可能时最不常用的，因此将其置换出去可以腾出空间给新的页面。

LUR 算法通常时使用一个数据结构去维护页面的使用历史，维护使用历史就是通过访问字段实现的。访问字段的位数和操作系统分配给该进程的页面数有关，比如分配 4 个页面，访问字段就是两位，16 个页面，访问字段就是 4 位，依此类推。如此，每一个页面的访问字段都可以不同，通过访问字段的不同，我们就可以判断页面的使用历史。

## 时钟算法
Clock 算法基于一个环形链表或者循环队列数据结构来管理页面的访问情况，用于选择置换的页面。Clock 算法的核心思想是通过使用一个指针（被称为时钟指针）在环形链表上遍历，检查页面是否被访问过。这个访问过同样需要我们上面说到的访问字段来表示，此访问字段只有一位。每个页面都与一个访问位相关联，标记该页面是否被访问过。 

当需要进行页面置换时，Clock 算法从时钟指针的位置开始遍历环形链表。如果当前页面访问位为 0，表示该页面最久未被访问，可以选择进行置换。将访问位设置为 1，继续遍历下一个页面。如果当前页面的访问位为 1，表示该页面最近被访问过，它仍然处于活跃状态。将访问位设置为 0，并继续遍历下一个页面如果遍历过程中找到一个访问位为 0 的页面，那么选择该页面进行置换。





# 9.解释进程同步和互斥，以及解决这些问题的方法
## 进程同步
> 是指多个**<font style="color:#DF2A3F;">并发执行的进程之间协调和管理他们的执行顺序，以确保他们按照一定的顺序时间间隔执行</font>**。比如说，你想和你的队友一起完成一个副本，你们需要相互配合，有时候等待对方的信号或者消息，有时候按照对方的要求执行某些动作，这就是进程同步。
>

## 互斥
> 指的**<font style="color:#DF2A3F;">是在某一时刻只允许一个进程访问某个资源。当一个进程正在使用共享资源时，其他进程不能同时访问该资源</font>**。比如说，你想要使用一个祭坛来祈愿，但是这个祭坛一次只能被一个人使用，如果有其他人也想要使用，他们就必须等待你使用完毕后再去使用，这就是进程互斥。
>

## 解决进程同步和互斥的问题方法
+ 使用信号量和 pv 操作。信号量少一种特殊的变量，他表示系统中某种资源的数量或者状态。PV 操作是对信号量进行增加或者减少对操作。
